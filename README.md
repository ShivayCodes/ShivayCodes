## 🚀 Featured Project

### [U.L.T.R.O.N 1.0](https://github.com/ShivayCodes/U.L.T.R.O.N-1.0)

A Python-based, offline-first desktop AI assistant with local memory, searchable knowledge, optional model backends, and a Windows-friendly Tkinter interface.

**Implemented capabilities**
- Desktop chat interface with light/dark themes, chat bubbles, timestamps, and model settings.
- Offline retrieval mode with persistent local conversation memory and knowledge storage.
- Optional Ollama and OpenAI-compatible model providers.
- Indexed local memory and knowledge search.
- Explicit opt-in conversation learning and user-directed web research.
- Streaming CSV ingestion for datasets up to 200 MB; ingestion adds retrieval knowledge and does not train a model.
- Permission-classified built-in tools and bounded arithmetic evaluation using an AST allowlist.

**Recent engineering milestones**
- Added and polished the Windows desktop interface.
- Integrated optional real-model provider support while retaining offline fallback.
- Added CSV learning-data ingestion and a WikiWhy dataset importer.
- Added indexed retrieval and permission-checked built-in tools.
- Published a source-level review and prioritized remediation plan in [fixes.md](https://github.com/ShivayCodes/U.L.T.R.O.N-1.0/blob/main/fixes.md).

<sub>Review transparency: the review report records issues and recommended fixes. Those findings should not be interpreted as completed source-code fixes; implementation and regression verification remain separate milestones.</sub>

## 🧠 How I Learn & Build

1. Start with fundamentals and precise questions.
2. Build a small, testable implementation.
3. Measure behavior instead of assuming it works.
4. Review edge cases, security, and failure modes.
5. Document findings and improve incrementally.

> Consistent, evidence-based improvement beats unsupported claims of expertise.

## 🔐 Security & Responsible Engineering

- Never commit API keys, passwords, access tokens, private keys, or real environment files.
- Use isolated environments and least-privilege permissions.
- Test security tools only on systems and applications I own or am authorized to assess.
- Treat model output and retrieved data as untrusted until verified.
- Prefer explicit permissions, reproducible tests, and transparent limitations.
